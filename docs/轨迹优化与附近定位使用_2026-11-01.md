# 轨迹优化和附近摆放定位使用说明

工作区 `/home/hui/diting-gazebo-feat-sentry-nav-simulation`。只保留原有双车场景、YAstar 与当前控制器；本轮没有接入 Kinodynamic A*、真机驱动、裁判返航或自动循环。

## 正常启动

先关闭旧仿真实例，再在新终端执行：

```bash
source /home/hui/diting-gazebo-feat-sentry-nav-simulation/source_all.bash
ros2 launch sentry_sim_bringup dual_sentry_simulation_launch.py use_rviz:=True
```

默认 LIO+YAstar；三点仍为 (-4,3.475)、(-2.5,3.475)、(0,0)。优化器在YAstar之后生成几何路径，原隧道BT继续使用专用直线轴线。原速度、完整车身、扫描0.8秒守卫保持。

## 出生位置与定位初猜

默认仿真出生 (-5.3,3,.3)、yaw=-π/2；地图初猜是base_footprint (-5.3,3,0)、yaw=-π/2。前者是真实模型位置，后者仅为匹配初猜，两者独立。

只模拟附近摆放误差（保持初猜默认）：

```bash
ros2 launch sentry_sim_bringup dual_sentry_simulation_launch.py \
  use_rviz:=True spawn_x:=-5.1 spawn_y:=3.15 spawn_yaw:=-1.4
```

若约定出生区域变动，需要独立提供该区域附近的地图初猜：initial_pose_x、initial_pose_y、initial_pose_z、initial_pose_yaw。未知任意位置的全场重定位未实现；三点是固定map坐标，不随出生位置平移。

查看可信定位和实际home记录：

```bash
ros2 topic echo /sentry_robot1/localization_status std_msgs/msg/String --qos-durability transient_local --qos-reliability reliable --once
ros2 topic echo /sentry_robot1/route_status std_msgs/msg/String --qos-durability transient_local --qos-reliability reliable --once
```

仅固定路线的startup节点等待可信状态以及原全部ready条件连续3秒，GT调试模式跳过GICP状态；直接RViz目标不经过该新增门控。home_pose是首次任务放行时的实际map/chassis位姿，只保存在本进程状态，重复任务不覆盖。未执行返航。

## 重复与取消

```bash
ros2 service call /sentry_robot1/start_route std_srvs/srv/Trigger '{}'
ros2 service call /sentry_robot1/cancel_route std_srvs/srv/Trigger '{}'
```

取消服务返回请求已发出后，还需看到同一run_id的idle/canceled。实际规划搜索由本地sentry_planner_server接入取消，系统Nav2未替换。普通非扩展插件内部只能调用前后检查取消；单次Eigen求解等区段也不可抢占。

## 轨迹优化对照与回退

当前两份仿真YAML的 planner_server.ros__parameters.GridBased.trajectory_optimization.enabled=true；仅设置此项为false可回到原YAstar几何路径，保持同一搜索算法。请在停止仿真后使用配置副本和params_file做对照，再启动；不在运行中改结构参数。

曲线发生完整车身碰撞、越界/未知格、偏离/长度/点数超限、数值失败或超预算时，自动退回已验证原路径；外部取消会停止整个规划请求，不走回退继续执行。默认30ms是合作式优化预算，不是整个规划动作的硬实时保证。

源码及完整边界见同目录《算法与边界说明.md》。最终验收结果见《修改与验收说明.md》。
