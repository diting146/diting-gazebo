# 包归属与受控构建

当前双车入口使用 `tools/build_current.bash` 受控构建，不合并源码、不删除上游包、不清理旧产物。下面的包归属按现有源码和安装路径核对。

## 包归属

根层负责仿真资源、Gazebo插件和当前全局规划实现：

| 包 | 根层源码位置 | 当前完整入口的作用 |
| --- | --- | --- |
| rmoss_gz_plugins | src/rmoss_gazebo/rmoss_gz_plugins | 麦轮Gazebo插件 |
| rmu_gazebo_simulator | src/rmu_gazebo_simulator/rmu_gazebo_simulator | 世界、手动车模型、模拟血量 |
| pb2025_robot_description | src/pb2025_robot_description | 当前模型所引用的网格资源 |
| pb_omni_pid_pursuit_controller | src/pb2025_sentry_nav/pb_omni_pid_pursuit_controller | YAstar根层构建所需碰撞库，完整运行由overlay副本覆盖 |
| tdt_yastar_planner | src/pb2025_sentry_nav/tdt_yastar_planner | YAstar及几何路径优化 |
| sentry_planner_server | src/pb2025_sentry_nav/sentry_planner_server | 含目标取消修正的Nav2规划服务 |

以下15个包在根层和overlay各保存一套源码。当前完整运行环境最后加载overlay，日常修改和增量构建应以 `sentry_nav/src/pb2025_sentry_nav/<包名>` 为当前导航副本：

```text
fake_vel_transform             ign_sim_pointcloud_tool
livox_ros_driver2               loam_interface
pb2025_nav_bringup              pb2025_sentry_nav
pb_nav2_plugins                pb_omni_pid_pursuit_controller
pb_teleop_twist_joy             point_lio
pointcloud_to_laserscan         sensor_scan_generation
small_gicp_relocalization       terrain_analysis
terrain_analysis_ext
```

其中根控制器仍须先构建，因为根YAstar直接使用它的碰撞接口；不能仅按“运行时使用overlay”就删除根控制器。现有overlay保留该7参数碰撞函数的兼容接口。今后若调整公共接口，应联动核对根YAstar的构建和链接，不将两份源码当成自动同步。

overlay另有 `sentry_nav/src/sentry_sim_bringup` 和 `sentry_nav/src/sentry_tunnel_bt`，合计17包本地构建闭包。17包是manifest依赖集合，不表示启动17个模块。独立 `sentry_runtime` 与旧RMOSS演示包不进入推荐构建集合，也不在本次删除。

## 使用入口

```bash
# 脚本从自身位置确定工程目录，可从任何目录执行。
export WS=/home/hui/diting-gazebo-feat-sentry-nav-simulation
bash "$WS/tools/build_current.bash" all --check
# 需要实际构建两层时执行；只构建单层则把all换成root或overlay。
bash "$WS/tools/build_current.bash" all
```

`root`仅选6包，`overlay`按 `sentry_sim_bringup` 的本地依赖闭包构建，发现闭包不再是上述17包或源码归属变化时停止。`all`顺序执行两个独立子环境，不向调用者终端写入环境。

脚本在干净子环境中运行：根层只加载ROS；overlay加载ROS及根 `install/local_setup.bash`，避免加载旧 `setup.bash` 中记录的父链。系统PATH固定；旧工作空间前缀、动态库/Python路径、虚拟环境、编译器与链接器flags不继承。网络代理及CA变量只转传不打印，构建并行度可用 `CMAKE_BUILD_PARALLEL_LEVEL` 控制。当前入口不支持自定义交叉工具链/编译器参数，避免隐含继承旧机器路径。

`--check`只调用关闭日志的 `colcon list` 并读取包路径、核心CMake缓存、已有安装索引，不运行 `colcon build`、不安装或下载依赖，不删除任何文件。缺少安装产物时明确标注未构建，不能把源码检查通过当成部署或运行验收。发现核心缓存指向旧源码目录、错误安装位置或根依赖指向overlay时拒绝继续，并保留现场。

新机器只复制源码和必要资源，先按[当前构建与依赖说明](当前构建与依赖说明_2026-11-06.md) 安装当前入口所需依赖。small_gicp联网/固定版本和旧可选依赖边界仍以该文档为准；脚本不安装依赖或更改依赖版本；实际构建small_gicp时仍可能联网获取该依赖。本轮仅运行语法与 `--check` 核验，没有实际全构建，不承诺干净机器完整构建已通过。

若需显式指定迁移后的源码目录，可追加 `--workspace /实际目录`。脚本使用系统 `/usr/bin/python3` 读取ROS包索引；自定义Python虚拟环境不参与该检查。
