## 导航启动与调试

```bash
source /home/hui/diting-gazebo-feat-sentry-nav-simulation/source_all.bash
ros2 launch sentry_sim_bringup dual_sentry_simulation_launch.py \
  spin_speed:=0 use_rviz:=True
```

等价于显式 localization:=lio。若需与先前真值链路比较，在同一入口添加 localization:=ground_truth。切换前关闭旧实例，不叠加两个世界。

LIO 的运行数据流为：

```text
Gazebo LiDAR ─→ 点云适配（转 chassis，补 ring/time）─→ Point-LIO
Gazebo IMU  ────────────────────────────────────→ Point-LIO
Point-LIO ─→ loam_interface / sensor_scan_generation ─→ odometry 与局部 TF
已采集 PCD + registered_scan ─→ small_gicp ─→ map → odom
上述估计位置与 TF ─→ Nav2 / YAstar / 控制器 ─→ 哨兵底盘
```

运行时的 map→odom 由 small_gicp 发布，odom→base_footprint 由 sensor_scan_generation 发布，base_footprint→chassis 为静态变换。Point-LIO 自己的 TF 关闭，避免重复父子关系。

初始位姿参数来自固定出生配置，是一次启动猜测，不是持续读取真值定位。small_gicp 是点云配准，依赖足够好的初始猜测和场地几何；这不等于任意位置、任意朝向都能全局搜索成功。RViz 的 2D Pose Estimate 发到 /sentry_robot1/initialpose 可修正估计，不会移动仿真模型。

LIO 专用速度网关在运行业务里程计连续到达两秒且末次数据不超过一秒时允许运动；使用稳态时钟保留暂停仿真时的断流停车，并对非零自旋请求渐变。这个就绪判断不代表已经通过 GICP 匹配质量或全局定位健康检测。原 Ground Truth 和手动车的网关保持原实现。

## 建图到底是什么

这里的建图是让哨兵用雷达与 IMU 估计运动，将多帧激光点积累到一个三维坐标系，保存为 PCD 文件，作为后续定位的参考。远端 mapping 入口只启动 Point-LIO 与接口节点，不运行 Nav2 和 small_gicp；当前接入沿用这一范围。

仍使用唯一双车入口：

```bash
source /home/hui/diting-gazebo-feat-sentry-nav-simulation/source_all.bash
ros2 launch sentry_sim_bringup dual_sentry_simulation_launch.py \
  localization:=lio slam:=True spin_speed:=0
```

等哨兵落地和 LIO 初始化后，需要人工让哨兵覆盖场地进行采集。采集哨兵的物理底盘命令输入是 /sentry_robot1/cmd_vel_chassis；手动车仍使用 /rm25_robot1/cmd_vel。建图时不要向未启动的导航控制器输入发命令。

Point-LIO 在正常退出时尝试将点云保存到：

```text
/home/hui/diting-gazebo-feat-sentry-nav-simulation/sentry_nav/src/pb2025_sentry_nav/point_lio/PCD/scans.pcd
```

强制杀死不能保证保存。这个文件是原始采集输出，不会自动覆盖当前运行先验，也不会自动变成二维地图。

当前建图没有接入回环优化或二维 SLAM 建图节点。新增 PCD 还需要检查覆盖、漂移、动态物体残留并降采样；默认建图坐标是 LIO 的启动坐标，不能假定等于已有场地 map。特别是哨兵从 (-5.3,3)、yaw=-90° 起步时，需要将采集坐标与二维地图对齐后才能作为新先验。已有 PGM/YAML 的生成与对齐是另一件事。

本轮只验证了 mapping 模块构成，没有重新采集地图或验收保存质量。

## 先验点云到底是什么

先验点云是定位开始前已经准备好的三维环境参考，相当于“先让机器人看过场地”。small_gicp 把当前观测点云与这份参考匹配，估计全局坐标修正，减少仅靠局部里程计累积的漂移。

| 文件/数据 | 用途 |
| --- | --- |
| maps/diting_3v3_field_mapped.pcd | 本次同步的传感器建图参考，242239 点，约 5.5 MiB；默认供 small_gicp 使用 |
| maps/diting_3v3_field.pcd | 原有模型几何采样点云，保留作几何对照，不是本次默认定位先验 |
| maps/diting_3v3_field.pgm + .yaml | Nav2 规划所用二维占据地图；与 PCD 用途不同，坐标需要一致 |
| /sentry_robot1/points_raw | 当前雷达观测，包含手动车等动态障碍，不是静态先验 |

远端 README 说明该 mapped PCD 来自传感器采集后的降采样；本轮核实了文件内容、点数以及与远端的哈希一致性，并完成短路线运行。不能仅凭远端旧验收数字，宣称本地全场地图已经重新验收。先验不包含实时移动物体的更新，动态障碍仍由当前传感器与 costmap 处理。

## 定位误差检测到底是什么

它是仿真评估工具：将估计 TF（map→sentry_robot1/chassis）与 Gazebo 真值放在同一时间比较。真值只进入 /sentry_robot1/reference/pose、/sentry_robot1/reference/odometry，不向运行链路发布 TF、不提供导航里程计、不发送控制命令。LIO 云台反馈使用 IMU。

```bash
source /home/hui/diting-gazebo-feat-sentry-nav-simulation/source_all.bash
ros2 topic echo /sentry_robot1/localization_error --once
```

消息为 geometry_msgs/Vector3Stamped：

- vector.x：估计 x 减真值 x，单位米。
- vector.y：估计 y 减真值 y，单位米。
- vector.z：估计 yaw 减真值 yaw，归一化到 [-pi,pi]，单位弧度；不是高度。

例如 dx=0.03、dy=0.04 表示平面误差 0.05 m；dyaw=0.01745 约为 1°。需要整段记录才能算平均误差、最大误差或 RMSE，一次采样不能当成全程精度。

监测器选取 TF 覆盖范围内的真值样本，并查询该样本同一时间的 TF；如果最新 TF 与样本相差超过 0.1 秒，就不输出这次比较，避免旋转过程中时间错位制造假误差。这个 0.1 秒是时间对齐限制，不是定位容许误差。

它不会自动修正定位、因误差大而停车、重新匹配或更换算法；没有完整的 valid/超时/健康状态机。TF 停更时可能继续发出旧时间对应的误差，因此要检查 header.stamp 是否推进。实机通常没有 Gazebo 真值，不能原样获得这种绝对误差，需要外部测量参考或另做匹配质量、时间与运动一致性监测。

## 本轮实际验证

构建与回归结果记录在 ACCEPTANCE.md。隔离双车 LIO 试验完成地图、扫描、定位里程计、误差消息与节点激活验证，手动车运动停车正常，YAstar 短路线返回 SUCCEEDED。终点平面误差约 0.00961 m，是该次采样，不是通用精度结论。

动态堵路、自旋、长时间漂移、定位丢失、全场地图覆盖和建图质量仍需分别验收。仿真中适配的等时点云与噪声参数不直接作为实机传感器标定。
