# 当前双车入口的构建与依赖说明

适用范围：Ubuntu 22.04、ROS 2 Humble、Gazebo Fortress，入口为 `sentry_sim_bringup dual_sentry_simulation_launch.py`。自动哨兵采用 LIO + small_gicp + YAstar，手动车只用于键盘干扰；默认固定三点任务、模拟血量及低血返航开启，真实裁判串口未接入。本文整理构建边界，不修改导航行为，也不把前置途径点试验加入默认任务。

以下包选择已用本机源码依赖图和 `colcon list` 核对；本次文档整改没有在干净机器下载依赖或重新构建，不代表已完成新机器安装验收。不要直接复制本机 build/install 到另一台机器，尤其不要跨CPU架构复制二进制。

## 先确认两层边界

根层当前入口需要6包：

```text
rmoss_gz_plugins
rmu_gazebo_simulator
pb2025_robot_description
pb_omni_pid_pursuit_controller
tdt_yastar_planner
sentry_planner_server
```

根控制器为 YAstar 的构建依赖；完整运行环境最后加载overlay控制器。根 `src/` 与 `sentry_nav/src/` 有15个同名包，属于两套独立源码。当前不合并或删除这些包。必须分层指定 `--base-paths src`；在根目录直接执行不限定发现路径的 `colcon build` 会发现同名包。

overlay使用 `--packages-up-to sentry_sim_bringup`，当前本地依赖闭包为17包：

```text
fake_vel_transform             ign_sim_pointcloud_tool
livox_ros_driver2               loam_interface
pb2025_nav_bringup              pb2025_sentry_nav
pb_nav2_plugins                pb_omni_pid_pursuit_controller
pb_teleop_twist_joy             point_lio
pointcloud_to_laserscan         sensor_scan_generation
sentry_sim_bringup             sentry_tunnel_bt
small_gicp_relocalization       terrain_analysis
terrain_analysis_ext
```

这是现有manifest的构建闭包，**不表示17包中的节点都会启动**。例如Point-LIO编译依赖Livox消息，当前仿真不会启动实体雷达驱动；地形和手柄相关依赖也不能仅依据manifest认定正在运行。独立 `sentry_runtime` 不在该构建选择中。

## 限定范围安装依赖

先安装ROS 2 Humble、Gazebo Fortress和colcon/rosdep工具；已有环境不重复初始化rosdep。以下命令假定这些基础工具已可用。新机器将 `WS` 改为实际源码目录，并在新的Bash终端操作：

```bash
source /opt/ros/humble/setup.bash
export WS=/home/hui/diting-gazebo-feat-sentry-nav-simulation

root_package_paths=(
  "$WS/src/rmoss_gazebo/rmoss_gz_plugins"
  "$WS/src/rmu_gazebo_simulator/rmu_gazebo_simulator"
  "$WS/src/pb2025_robot_description"
  "$WS/src/pb2025_sentry_nav/pb_omni_pid_pursuit_controller"
  "$WS/src/pb2025_sentry_nav/tdt_yastar_planner"
  "$WS/src/pb2025_sentry_nav/sentry_planner_server"
)

rosdep update
rosdep install --from-paths "${root_package_paths[@]}" "$WS/sentry_nav/src" \
  --ignore-src --rosdistro humble -y \
  --skip-keys "rmoss_gz_resources sdformat_tools"

# rmoss_gz_plugins的现有manifest未列全这些CMake开发库，另行明确安装。
sudo apt install libignition-gazebo6-dev libignition-msgs8-dev libignition-transport11-dev
```

这里跳过两个key有明确限定：`pb2025_robot_description` 旧manifest声明 `rmoss_gz_resources`、`sdformat_tools`，但当前双车入口只使用该包已有模型资源路径，不加载其旧 `robot_description_launch.py`。当前哨兵、手动车及场地模型引用的资源在本工程已存在；旧描述入口第16行才导入 `sdformat_tools.urdf_generator`。上述skip不是安装了这些依赖，也不能用于保证旧描述、旧RMOSS或其他未验收入口可用。

`rmoss_gz_base`、`rmoss_gz_bridge` 和 `rmoss_gz_cam` 仍在源码中，但不属于当前推荐根构建集合；它们需要的 `rmoss_interfaces` 不因此被安装。不要改为对根下所有源码运行rosdep后忽略报错，也不要为了绕过报错删除这些上游包。若要使用旧入口，先按各上游依赖清单补齐并单独验收。

另有两项机器迁移条件：

- small_gicp当前仍由CMake `FetchContent` 从上游 `master` 获取；首次构建需要网络，现状不能保证离线构建或不同日期依赖版本一致。固定版本/离线缓存属于后续依赖整改，不在本文中更改。
- Livox驱动源码中包含amd64和arm64 SDK共享库，Point-LIO仍有编译期消息依赖；迁移时保留对应文件和许可证，并使用目标机器重新构建。不能因仿真未启动驱动而直接删除该编译依赖。

## 推荐受控构建入口

依赖安装完成后，优先使用受控入口；它按当前根6包、overlay17包选择构建，并为每一层创建独立干净环境，避免把当前终端中的overlay反向记入根构建父链。包归属和检查边界见[包归属与受控构建](包归属与受控构建_2026-11-06.md)。

```bash
export WS=/home/hui/diting-gazebo-feat-sentry-nav-simulation
# 只检查源码归属及已有安装/缓存，不构建、不安装依赖或下载。
bash "$WS/tools/build_current.bash" all --check
# 确认依赖齐全后才执行实际构建；也可分别使用root或overlay。
bash "$WS/tools/build_current.bash" all
```

脚本不清理旧产物；核心缓存指向错误源码或根依赖指向overlay时会拒绝继续。`--check`通过不能代替真实构建或仿真验收；未安装的包会明确标注。以下详细手动命令保留，供核对及针对性增量操作。

## 按顺序手动构建

**采用下方手动命令时，使用新终端，先只加载ROS。**不要先加载 `source_all.bash` 再构建根层，否则overlay环境可能被记录为根安装的父链。构建失败时先修复缺失依赖，不继续启动半成品。

```bash
source /opt/ros/humble/setup.bash
export WS=/home/hui/diting-gazebo-feat-sentry-nav-simulation
cd "$WS"
colcon build --base-paths src --symlink-install \
  --packages-select rmoss_gz_plugins rmu_gazebo_simulator pb2025_robot_description \
  pb_omni_pid_pursuit_controller tdt_yastar_planner sentry_planner_server \
  --cmake-args -DCMAKE_BUILD_TYPE=Release

source "$WS/install/setup.bash"
cd "$WS/sentry_nav"
colcon build --base-paths src --symlink-install \
  --packages-up-to sentry_sim_bringup --cmake-args -DCMAKE_BUILD_TYPE=Release
```

若机器内存较小，可给两层构建增加 `--executor sequential`，并按机器资源设置 `CMAKE_BUILD_PARALLEL_LEVEL`；这只控制构建并行度，不调整运行时速度或控制频率。根层和overlay的 `build/install/log` 不互相复制。

## 加载、核对、启动

两层均成功后另开终端，仍使用原来的启动入口：

```bash
export WS=/home/hui/diting-gazebo-feat-sentry-nav-simulation
source "$WS/source_all.bash"

ros2 pkg prefix tdt_yastar_planner
ros2 pkg prefix sentry_planner_server
ros2 pkg prefix pb_omni_pid_pursuit_controller
ros2 pkg prefix sentry_sim_bringup

ros2 launch sentry_sim_bringup dual_sentry_simulation_launch.py use_rviz:=True
```

前两个prefix应位于根 `install/`，后两个位于 `sentry_nav/install/`。`source_all.bash`顺序为ROS→根→overlay，键盘和扣血终端也加载同一环境，保持ROS域和DDS设置一致。启动前关闭旧完整实例，避免叠加Gazebo世界。

完整任务操作见[导航工作区说明](../sentry_nav/README.md)。普通增量修改只在对应层构建具体包；依赖未构建时不能把 `--packages-select` 当作自动补齐依赖的命令。当前未修改运行环境脚本、launch、参数、地图或模型。
