# 模拟扣血返出生点

本功能沿用唯一双车入口和原三点任务节点。自动哨兵完成或正在执行三点任务时，模拟血量严格小于 50 将请求返回已记录的实际出生位姿。手动车不接入血量和返航。

## 操作

先关闭旧完整仿真实例，在新终端加载环境并启动：

```bash
source /home/hui/diting-gazebo-feat-sentry-nav-simulation/source_all.bash
ros2 launch sentry_sim_bringup dual_sentry_simulation_launch.py use_rviz:=True
```

保留出洞启旋测试时，在同一命令末尾添加 `spin_speed:=3.14`。三点正常到达后继续自旋；扣血返航时先关闭自旋。

等待首次可信定位就绪并记录实际出生位姿后，在另一终端操作：

```bash
source /home/hui/diting-gazebo-feat-sentry-nav-simulation/source_all.bash

# 每次发布都会继续扣血。满血 100 时扣 51，变为 49 后触发返航。
ros2 topic pub --once /referee/sentry_robot1/damage std_msgs/msg/Int32 '{data: 51}'
```

阈值为严格 `< 50`，100 扣 50 后不会触发。血量节点在每次重新启动时恢复 100；重复发正伤害会继续扣血，持续低血不会重复并发发送返航目标。

成功返航后可手动回血，允许下一次低血再返航。先查看当前实际血量，再操作血量源；以下负伤害命令**仅适用于当前恰为49血**：

```bash
ros2 topic echo /referee/sentry_robot1/hp std_msgs/msg/Int32 --once

# 确认当前为49后，加51恢复到100。damage是增量，负数表示回血。
ros2 topic pub --once /referee/sentry_robot1/damage std_msgs/msg/Int32 '{data: -51}'

# 等下一次血量发布，确认已是100。
ros2 topic echo /referee/sentry_robot1/hp std_msgs/msg/Int32 --once
ros2 topic echo /sentry_robot1/route_status std_msgs/msg/String \
  --qos-durability transient_local --qos-reliability reliable --once
```

`damage: -51` 是在当前血量上加51，不是设置为100；当前不是49时应按实际差值计算。不要直接向 `/referee/sentry_robot1/hp` 发布100来代替回血，实际血量源每秒发布的值会将它覆盖。成功返航且空闲、有 `home_pose`、没有待处理返航，并收到最新血量不低于100后，`low_hp_latched` 才变为 `false`；50或99均不解锁。回血不自动出发，也不覆盖首次记录的出生位姿。

解锁后可手动发送RViz目标，等该目标成功完成，再扣51，使100降至49，触发第二次返回同一出生位姿。手动目标进行中时的接管不在本次范围。

## 状态检查

```bash
# 查看实际模拟血量，默认每秒更新一次。
ros2 topic echo /referee/sentry_robot1/hp std_msgs/msg/Int32 --once

# 任务状态为 JSON，含首次可信就绪后锁存的 home_pose。
ros2 topic echo /sentry_robot1/route_status std_msgs/msg/String \
  --qos-durability transient_local --qos-reliability reliable --once
```

由任务节点统一处理：停旋、取消已有导航并等待终态、通过 Nav2 导航回已记录出生位姿。返航目标取自 `home_pose`，不直接写死为仿真默认坐标，也不使用 Gazebo 真值替代定位记录。需要由 Nav2 重新规划，是否经过隧道由现有导航逻辑与可通行条件决定。返航到达使用现有目标容差，不保证精确复原人工摆放误差。

当前支持手动通过负伤害回血与成功返航后的重新允许返航，不增加自动回血、返航后等待再出发、自动循环、裁判增益判定或真机协议。取消任务仍使用原 `/sentry_robot1/cancel_route` 服务。没有可信出生记录时不能发往猜测出生点；定位和 Nav2 未就绪时不能把收到扣血视为返航成功。

## 启动范围与通信

- 默认仅固定任务启用且非建图时启动 `sim_referee_hp`，机器人列表只有 `sentry_robot1`，初始血量 100。
- `referee_hp.py` 的旧返航阈值设置为 0，禁止它自行发出第二套 Nav2 目标；任务节点的返航阈值为 50。
- `auto_nav_to_origin:=False enable_route_task:=True route_auto_start:=False` 仍保留任务及模拟血量，三点等待人工调用 `start_route`。
- `auto_nav_to_origin:=False enable_route_task:=False` 或 `slam:=True` 不启动模拟血量和固定任务。
- `enable_sim_referee:=False` 仅关闭本模拟血量源和低血自动返航，保留三点任务。此开关不等于已配置真实裁判接入。

链路为 `damage (Int32) → referee_hp → hp (Int32, 1 Hz) → startup_navigation`。没有串口设备打开、波特率或裁判二进制帧。当前不需要启动旧 `dual_sentry_runtime_launch.py`，它仍按旧双自动哨兵场景配置。名称为 `sim_serial_gateway` 的节点是底盘模拟速度网关，与裁判串口无关。


## 返航状态与边界

`route_status` 保留原 `run_id/state/last_result/home_pose`，新增 `task_kind/hp/low_hp_latched/return_pending/return_state/return_result`。原三点终态之后返航使用新的 run_id，`task_kind=return_home`；最终看 `return_result.outcome=succeeded`，不能把旧三点 canceled 当作返航成功。返航前关闭自旋，等新鲜里程计连续0.5秒低速，再通过原连续3秒就绪检查，因此接到低血状态后通常会有几秒停车确认。

- 尚未记录可信 `home_pose` 就扣到低血，当前明确失败并停住，不猜测出生点；请在首次定位可信、出生位姿已记录后测试。
- 每轮低血只触发一次；成功返航、空闲、有出生记录、无待处理返航且最新血量不低于100后重新允许下一轮。返航途中回血不会提前解锁，只有成功终态时血量仍不低于100才解锁。取消、失败、拒绝或终态未知不因回血自动解锁；不自动出发。
- 动作请求/响应异常且无法确认旧目标终态时，保留busy并持续停旋、零速，不冒险并发派发返航。明确拒绝和真实动作终态正常收尾。
- 当前只针对本任务节点拥有的三点和返航目标精确取消；可以在成功返航并回血解锁后发送RViz目标，等其完成再扣血。不要与任务节点同时提交并行导航目标，本次未扩展外部活跃目标接管。
- 保留原碰撞、扫描/TF时效和洞内保护。洞内中断起步与动态堵塞仍受当前Nav2可通行性约束，失败会停车并报告，不通过删除保护保证到达。


## 首次接入的历史验证结果

下列为首次接入低血返航时的历史结果：局部构建成功，214项pytest通过。6次真实LIO仿真分别覆盖到达后自旋、在途取消、50/49阈值、实际出生偏移、洞内中断，以及原带界面入口，均成功返航并全停；这些样本未覆盖回血后二次返航。

| 场景 | 返航结果 | 返航导航墙钟 | 停车后距记录home（map） |
|---|---|---:|---:|
| 三点完成、持续自旋后扣51 | SUCCEEDED / 全停 | 22.112s | 0.450m |
| 出洞续航中扣51、取消三点后返航 | SUCCEEDED / 全停 | 26.013s | 0.333m |
| 先扣50不触发、再扣1触发 | SUCCEEDED / 全停 | 22.673s | 0.241m |
| 真实出生(-5.1,3.15)、初猜保持默认 | SUCCEEDED / 全停 | 21.193s | 0.363m |
| 洞内收到49、取消前进后返航 | SUCCEEDED / 全停 | 4.364s | 0.332m |
| 原GUI入口、默认25s出生等待、扣51 | SUCCEEDED / 全停 | 24.333s | 0.334m |

沿用0.5m普通目标到达区域，未增加精准停靠或恢复出生朝向。有限样本不能替代长期/动态堵塞验收。退出阶段原HP节点仍可能有shutdown traceback，本轮测试已清理、未推送Git。

## 回血后二次返航修改的验证状态

重新允许返航的状态机已通过代码审查、24项低血返航测试和全包230项Python测试；局部构建及标准 `colcon test` 均通过（230项、0失败、0错误）。独立ROS域223、独立Gazebo分区完成真实LIO/YAstar两轮闭环：三点成功并自旋 → 扣51返航成功 → 负伤害加51恢复100 → 外部NavigateToPose绕洞到达(0,0) → 再扣51返航成功。外部目标由测试ActionClient模拟RViz发送，不冒充人工点击验收。

两次返航分别为 `run_id=2/3`，距同一记录出生点0.462m/0.379m，均落入原0.5m到达区，稳定停车窗口约0.49s；home仅记录一次。顶层action核验为一单三点、两单返航和一单外部目标，全部SUCCEEDED，无顶层目标重叠；持续49未增加run_id。HP唯一源为 `sim_referee_hp`，回血后仍idle，不自动出发。测试实例已清理，用户原实例未停止；旧实例必须正常关闭再重启，才会加载新逻辑。
