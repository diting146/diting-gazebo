# 场地几何配置与覆盖顺序

正常双车入口及其 LIO/GT 导航组件统一读取 `sentry_nav/src/sentry_sim_bringup/config/scene_geometry.yaml`，生成两个BT节点的隧道参数和YAstar软代价ROI；固定任务与单独启动的 `startup_navigation` 使用同一文件提供默认三点及yaw。修改文件后重启相关节点，配置不会在运行中热更新。

可在原启动命令末尾添加 `scene_file:=/绝对路径/scene_geometry.yaml`。安装资源位于 `sentry_sim_bringup` 的share目录 `config/scene_geometry.yaml`。此配置只描述导航场地坐标，不修改Gazebo场地模型、地图PGM、出生点、速度、碰撞轮廓或通行阈值；替换后仍需人工确认与物理场地、地图及定位坐标一致。

当前数值保持原样：

| 项目 | 北侧 | 南侧 |
| --- | --- | --- |
| 隧道x范围/m | [-3.5, -1.5] | [1.5, 3.5] |
| 中线y/m | 3.475 | -3.475 |
| 共同半宽/m | 0.4 | 0.4 |
| 软代价ROI [xmin,ymin,xmax,ymax]/m | [-4,3.06,-1,3.86] | [1,-3.86,4,-3.06] |

默认三点仍为入口(-4,3.475)、洞中(-2.5,3.475)、目标(0,0)，yaw=0。ROI不按中心线自动纠偏；只影响软代价，254/255障碍、完整车体碰撞检查继续生效。

## 覆盖顺序

1. 默认 `scene_file` 指向包内文件；显式路径替换正常场景数据。
2. `route_points` 省略或空字符串使用scene三点；显式六个有限数字覆盖路线，`route_yaw`显式有限弧度覆盖scene yaw。显式 `[]`、空列表、`null`仍拒绝，避免静默出发。仍限定三个点，不支持追加第四点。
3. 使用包内参数文件时，scene覆盖生成参数中的 `GridBased.tunnel_cost_regions`；指定其他路径的 `params_file` 时保留该文件自带ROI。同一个包内文件的显式路径仍算内置配置。其他既有参数覆盖规则不变。
4. 使用包内BT目录时，scene覆盖生成XML中 `TunnelPassage/TunnelRouteGuard` 的 `tunnels` 和 `tunnel_half_width`；指定其他 `bt_xml_dir` 时保留用户XML几何。旧三元组格式和插件半宽默认0.4保留兼容。
5. 因此显式自定义参数/BT的几何一致性由调用者维护；仅替换scene不会静默改写自定义文件。包内YAML/XML/C++中的旧数字仅兼容回退，单改这些旧数字不会改变正常入口生成结果。

## 校验与能力边界

scene要求固定版本1、map坐标系、两条沿x轴的隧道、共同正半宽，以及三对XY和一个yaw。加载器拒绝重复/非字符串键、缺失或未知字段、布尔冒充数值、NaN/Inf、倒置区间及重复id。没有加入旋转隧道、额外途径点或自动改场地图形的功能。

在洞内或车尾仍跨洞口时发新任务，当前仍按独立安全修复停车并明确失败，不因场地配置归一而获得自动退洞功能。已有任务取消确认、低血延后返航与显式重试状态机不变。
