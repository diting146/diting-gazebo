# Sentry tunnel preparation BT node

`libsentry_tunnel_bt_node.so`注册 `TunnelPassage`、`TunnelRouteGuard` 和同步辅助节点 `TunnelFinalGoal`、`TunnelTaskCompleted`。此插件在现有 Nav2 任务内部执行入口准备和穿越，不创建常驻目标发布节点，不调用 `NavigateToPose`，也不修改传入的最终 `goal`。

LIO/GT参数文件先为两个标准私有节点 `bt_navigator_navigate_to_pose_rclcpp_node`、`bt_navigator_navigate_through_poses_rclcpp_node` 显式配置 `use_sim_time: true`，使时钟在构造时生效。构造期再将Nav2私有BT client node的标准 `use_sim_time` 参数与显式同名BT端口同步（本仿真包默认true，launch须传入实际值）。所有时效比较、时间停滞/回退检查和内部action时间戳使用同一ROS clock，不混用仿真秒与系统纪元时间。真机端口应为false。

## 集成语义

放在初次 `ComputePathToPose` 后、普通持续重规划/跟踪流水线前。每个新任务先只读查询两份 costmap 的完整 padded footprint 与新鲜 map→底盘 TF，最多等待3秒；不能取得或两份轮廓不一致时明确失败，不放行普通导航。车身任何部分仍与隧道矩形重叠时，新任务停车失败并报告 `new_task_body_overlaps_tunnel_requires_manual_exit`；低血返航使用相同检查，当前不自动退洞，须先人工安全移出。之前通行失败的重试仍报告 `in_tunnel_failure_requires_manual_exit`。

只有路径按顺序完整穿过入口和出口，且当前车身已完全在洞外，才接管原准备流程。目标仅在洞内、起于洞内、侧向进入等部分路径明确报告 `partial_tunnel_route_requires_complete_passage` 并失败，不再交给普通 FollowPath。完全在外且路径不接触隧道时直接交还普通导航；被动分类不发布零速度、自旋或限速命令。普通跟踪途中，`TunnelRouteGuard`用线段与隧道矩形相交检查继续拦截完整及部分进入，先halt普通跟踪，再使用既有有界Wait/重试回到准备或明确拒绝。不会因为路径采样稀疏而漏掉两采样点之间的穿越。该交接消耗原恢复重试预算，不新增无限循环。

两个导航action使用同一过洞插件。`NavigateThroughPoses`由`TunnelFinalGoal`保存最后目标，完整出洞后只消费实际底盘轨迹按顺序经过的中间点（0.15m通过半径），最终点永远保留，之后交回标准多点规划与跟踪。未实际经过的点不删除；前缀点顺序必须与实际行驶顺序一致，不能把出洞后的坐标关系当作已经到达。

默认地图标定为北侧 `x=[-3.5,-1.5], y=3.475`、南侧 `x=[1.5,3.5], y=-3.475`，物理半宽0.4m。两个节点须使用相同标定；通过 `tunnels` 端口输入 `xmin;xmax;y` 三元组，可覆盖这些仿真坐标。不会强制使用隧道，也不会在路线上没有隧道时寻找隧道。

正常内置启动由 `sentry_sim_bringup/config/scene_geometry.yaml` 向两个节点注入相同三元组和 `tunnel_half_width`（共同半宽，兼容默认0.4m）。插件及XML字面量只作兼容回退；配置来源和自定义BT优先级见[场地几何配置说明](../../../docs/场地几何配置_2026-11-06.md)。

## 通行阶段

1. 核验实际里程计、扫描、底盘 TF、全局/局部代价地图及其更新时间；查询实际 costmap `footprint` 与 `footprint_padding`，两图必须一致，使用真实带padding多边形推导所有包络。
2. 通过原 `ComputePathToPose` / `FollowPath` 导航到入口外0.5m。距该等待点较远时解除区域限速，使用普通道路速度；进入`approach_slowdown_distance`（默认1.5m）后锁存0.3m/s限制，直到完成入口对齐，距离抖动不会重新加速。每条新隧道重新计算，近处起步立即限速。
3. 到达洞外并停车稳定后，若朝向未达标，先在两图完整填充旋转外接圆保护下对齐真实 chassis yaw。默认上限0.6rad/s，近目标保持不低于0.1rad/s的有效角速度；根据真实底盘TF角速度和时间滞后预测制动，误差≤0.2°时停止，误差≤2°且实际低速稳定0.5s后进入居中。已满足朝向条件时跳过转向；不增加失败旋转动作。
4. 转正后进行连续有界闭环居中，默认最高0.15m/s且不超过approach_speed，使用TF位移差分与数据延迟预测停车位置，当前和未来完整多边形扫掠检查始终保留。只在接近位置时停车，并读取停车后的TF与稳定0.5s的实际低速度重新验收横向误差≤1.5cm；未达标再纠正，不再每0.08s强制停稳。纵向允许停在名义等待点外侧30cm内。全部准备步骤共享60s预算，必要的重新转正最多3次；当前通过中偏轴阈值为6cm（2026-11-03仿真试验设置）。
5. 转正后重新调用 YAstar 规划出口外0.6m目标，确认仍穿越同一隧道；专用阶段沿轴线构造25mm采样路径，逐段通过全局原始代价地图完整车身扫掠检查，再由原控制器跟踪。线速度限制0.8m/s；动态障碍和局部扫掠仍由原控制器检查。
6. 验证车尾完全出洞且停车后解除区域限速，对原最终目标重新规划；有下一条未处理的隧道则依路径顺序重复，否则成功交还普通导航。最多2条候选。

`speed_limit=0` 表示解除区域限速，停车使用显式零 `Twist`；两者含义不同。有效限速依赖现有控制器已实现 `setSpeedLimit`。内部FollowPath使用可配置`controller_id`（默认FollowPathTunnel）和`goal_checker_id`（默认tunnel_goal_checker），普通最终导航继续使用独立的普通控制与目标检查配置。

## 安全边界与观测

- 直接精确平移与转向发往 `cmd_vel_controller`，继续经过原平滑、fake坐标转换和网关，未旁路最终速度链路。
- 接近、入口对齐和洞内通行要求实际自旋指令为0。固定三点任务可通过 `exit_spin_speed` 明确指定安全出洞后的目标自旋；仅FOLLOW_CONTINUATION允许该已授权值。其他意外非零/非有限指令会清零并拒绝。不会恢复来源不明的自旋状态。
- 未知格255、致命格254和越界均拒绝；253及更低软代价不被当作物理实体。
- 数据过期、时间倒退/停止、阶段超时、当前/未来碰撞、通过中明显偏离轴线、规划或控制失败均停车并返回失败，使用外层既有有界重试，不增加自动倒车或失败旋转。
- `tunnel_passage/state` 和 `TUNNEL_STAGE` 日志记录阶段、方向、候选编号、最终目标和失败原因。最终导航成功仍由原 Nav2 导航 action 报告，插件自身完成不等于最终点到达。
- 动态改变 footprint 的消息接口尚未支持；当前读取的是 costmap 参数。任意起始朝向选路、洞内目标准备、洞内重新对齐，以及真实场地标定/制动距离不在首阶段保证范围。
- 通行中失败且整车仍与该隧道区域重叠时锁定失败，有界重试后明确返回ABORTED；不能因重试起点已在洞内而跳过专用流程。需人工安全移出后再重试；不会自动倒车出洞。
- 普通失败进入 `CANCELING`，持续零速并等内部动作真正终态后才交还外层恢复。取消响应仅表示进入取消中，不能当成停车成功。`halt` 及销毁遇到迟到accept时，独立动作回调上下文仍按原UUID精准取消并持续发零，直到终态或ROS context关闭；不会全服务器取消其他客户端目标。


2026-10-30优化版默认普通上限1.0m/s、入口接近0.3m/s、专用通行0.8m/s。普通到点半径0.5m与隧道内部0.15m检查器分开；普通/隧道接近减速距离分别0.9/0.6m。此处通行速度是上限，不代表全程匀速。

## 2026-11-01 洞内偏差触发诊断

`FOLLOW_PASSAGE` 原有 `yaw_error > yaw_tolerance * 1.5` 或 `abs(y-center_y) > 0.035m` 的比较、阈值、停车、锁存和外层恢复均保持不变。仅在该判断触发时，额外输出一条 `TUNNEL_FAILURE_DIAGNOSTIC {JSON}`，并向相对话题 `tunnel_passage/diagnostic` 发布相同JSON（可靠、transient-local、深度1）。可通过BT端口 `deviation_diagnostic_topic` 覆盖话题。重复BT重试被锁存拒绝时不覆盖原始触发数据；无每帧日志。

该记录包括独立 `yaw_exceeded` / `lateral_exceeded`、数值与阈值（角度单位rad、距离m）、判定使用的map→车体位姿及源时间、采集ROS/steady时间、odom/scan源年龄及接收墙钟年龄。`map_odom_at_pose_stamp` 与 `odom_body_at_pose_stamp` 采用判定TF的同一源时间，仅查询TF缓存；不能获得则明确 `available:false` 和错误，不等待、不用最新/单位变换代替。`odom_message` 则保留其本身时间戳，不能当作与判定同一帧。

可选订阅 `localization_status`（BT端口 `localization_status_topic`），仅保存最近接收状态，不参与门控。`localization_status.last_message_json` 为经过JSON转义的原始JSON字符串，二次解析可获得GICP `trusted`、`stamp_ns`、`latest_scan_stamp_ns`、`translation_step`、`rotation_step` 等原始字段。`sample_relation=last_received_not_time_synchronized` 明确标注该状态仅是最近接收值，并非与判定同一时刻的状态。记录接收时间及墙钟年龄，最多保存8192字节，超长明确标记 `truncated:true`。GT没有此发布者时 `available:false`，正常通行不受影响。非有限数值写成JSON `null`，诊断异常不会覆盖原始失败原因。

观察命令（与导航环境和ROS_DOMAIN_ID一致）：

```bash
ros2 topic echo /sentry_robot1/tunnel_passage/diagnostic \
  std_msgs/msg/String --qos-reliability reliable --qos-durability transient_local --once
```

## 2026-11-03 三点连续通行

当前多点BT启用 `continuous_path=true`：限定入口点、洞内轴线中点、洞外最终点这组三点、单条隧道；额外/偏轴途径点、洞内最终点、多洞等不满足条件的任务保留原停稳流程。单目标BT不改变。固定路线仍为 `(-4,3.475) → (-2.5,3.475) → (0,0)`。

接近入口时异步预取出口之后到最终目标的YAstar路径。核对实际控制器禁旋配置和最大前视距离，延长出口轴线以容纳完整车身、前视和余量，然后拼接洞内轴线与后续路径，并重新做全车扫掠验证。中间两点只有实际轨迹按顺序经过后才消费，不能仅凭路径几何删除。

带速准备只在入口0.60m内使用上游0.20m对齐位置，远段保持原已验证直线。朝向已对齐且横偏≤0.04m、距入口尚有0.10m余量时保留前向分量；指令向量仍受rolling速度限制，越过上游位置后不反向回拉。实际横偏≤1.5cm、纵向进入原等待带、朝向≤0.2°且TF差分角速度≤0.02rad/s时直接交给连续FollowPath，不追加正常停车或0.5s停稳。若无法行进对齐，原安全精调分支仍可介入。

连续FollowPath从入口跟踪到原最终目标，入口/出口不作为控制器终点。车尾每个带padding footprint顶点清出出口≥1cm且中心清出≥0.30m后，保持同一FollowPath并解除隧道限速；出洞后保留3Hz异步重规划，采用FollowPath pending-goal preempt更新路径，不cancel旧控制目标、不等候新路径时停车。新旧UUID都保留到真实终态，取消/异常涵盖所有未终结代。最终到达才停车并设置task_completed，BT跳过再次启动普通跟踪。

连续阶段状态：`following_tunnel_axis_continuous`、`full_body_exit_continuing_without_stop`、`continuous_final_goal_reached`。当前洞内6cm横偏、朝向、扫描/TF/costmap时效、时间异常和碰撞检查仍生效；异常停车不属于应删除的正常接缝等待。运行中的实例不能热加载插件，需关闭后重新启动。


本轮最终构建69项GTest通过。相同最终库的3次独立LIO出生首程均SUCCEEDED，导航墙钟18.761/18.632/19.242s（不含仿真启动与定位就绪等待）；入口接缝最低实速0.045–0.055m/s，出口0.333–0.347m/s，窗口内均无低于0.03m/s的停车段。入口仍有短暂低速对齐，并非匀速通过。洞内/出洞后取消实测在0.852/0.563仿真秒内降至≤0.03m/s并持续稳定，取消不绕过原制动链路。洞内原“终态后1秒窗口”脚本因包含刹车末段报false，完整后观测已补证，原结果保留。

越过入口纵向允许带时退回原停稳精调，避免禁止回拉后无进展等到60秒。开发候选曾复现LIO横偏越过3.5cm的保护停车；本轮未放宽该门槛，3次最终通行样本不代表长期成功率保证。详细版本哈希、原始失败、取消和接缝速度证据保存在工作记录目录“三点连续通行_2026-11-03”。

## 2026-11-03 出洞启旋与云台世界朝向补偿

固定三点任务开启时，双车入口沿用 `spin_speed`：默认0仍全程不自旋；显式3.14时fake和网关初值均为0，BT的 `exit_spin_speed` 保存3.14。接近、对齐和穿洞均维持零自旋；底盘为了对齐而转向是有界准备动作。整车离洞后继续原FollowPath，中心距出口达到带padding足迹外接半径加5cm，且剩余全局路径圆盘扫掠、当前局部圆盘、未来0.5秒控制指令和局部前方走廊均安全时，一次性发布目标自旋，不增加停车交接。异步重规划回复的已行驶前缀裁掉后再按旋转包络验证，保留精确最终目标。

成功到达后默认只停平移、保留自旋（`keep_exit_spin_at_goal=true`）；取消、失败、动作迟到取消的后台清理均同时发 `cmd_spin=0` 和零Twist。重发固定任务先关闭上轮自旋并等待真实低速度，再开始准备。普通单点RViz任务没有自动出洞启旋；关闭固定任务时显式 `spin_speed` 保持原立即自旋语义。

LIO使用底盘IMU，GT使用真实底盘里程计，两者均由同一个 `sensor_gimbal_world_lock` executable按真实关节角补偿。补偿保持雷达初始世界yaw；云台相对底盘反向转动是必要动作，雷达位置仍随车平移。新增底盘角速度前馈和有界误差积分，默认 `yaw_feedforward_time_sec=0.17`、`yaw_integral_gain=2.0`、`yaw_integral_limit=0.35`；这些是仿真位置伺服校准参数，不是已标定的真机云台增益。NaN、无效四元数、过期反馈不产生新命令，时间回退重置并重新锁定。该修正未改模型、TF反馈源、足迹、洞内6cm偏差门槛或原控制器。
